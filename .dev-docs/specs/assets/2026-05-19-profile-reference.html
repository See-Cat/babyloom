⑤ 永久删除二次确认 Modal(规范 §4.7)
设计要点
  • Me hub 结构:用户卡 / 正在记录 / 家庭管理 / 其他 / 退出登录。每段用 sect-title 分隔
  • 列表图标用 inline SVG,不用 emoji(新增规范):emoji 在不同 OS / 浏览器渲染极不一致(👶 大而彩,🗑 小而简,👨‍👩‍👧 等 ZWJ 复合 emoji 会渲染失败落到字符 fallback)。规定:UI 系统图标必须用 inline SVG(Lucide / Heroicons 风,24x24 viewBox,1.8px stroke,currentColor 着色,无 fill);emoji 仅用作内容(用户输入/正文)
  • "正在记录" featured card — 独立视觉:primary-bg 浅薄荷底 + 1.5px 半透明 mint 边 + 大头像 + 名字 + 月龄,右侧 切换 › 白底胶囊按钮(带浅 mint 按压阴影)。和下方的灰底 list-card 形成层次差异,体现"这是激活态"
  • 单宝宝场景 — 当全家只有 1 个宝宝时:切换按钮和 chevron 整体隐藏,卡片不可点;只保留头像 + 名字 + 月龄作为信息展示。区分"只能看"和"可切换"两种状态,避免误触
  • 退出登录 — 改为独立的居中红字按钮(不再是 list-card 包裹一行的尴尬结构):surface 底、红色文字、无图标、居中。:active 时 error-bg 浅红反馈
  • 角色权限可见性(三处分支需在实施时严格判断):
    • 用户卡 role badge:owner = "家庭主理人"(mint-bg)/ editor = "编辑成员"(surface-2)/ viewer = "仅查看"(灰)
    • "家庭管理"分组(宝宝 / 成员 / 里程碑):仅 owner 可见。editor 和 viewer 完全不显示这一整段(包括 sect-title)
    • "回收站"行(在"其他"分组内):owner 与 editor 可见,viewer 不显示
  • 宝宝管理(②):卡片列表;当前"记录中"用 mint outline + primary-bg 浅底 + "记录中"标签。点其他卡片切换 → server-side preference 更新 + Toast。点 chevron 进 /profile/babies/[id] 编辑详情。底部 dashed "+ 添加宝宝"跳 /onboarding/baby
  • 回收站(③ + ④):
    • 无自动清除策略:删除的记录无限期留在回收站,直到 owner 手动永久清除
    • info-bar 文案:"删除的记录会留在这里,可随时恢复"(不提"主理人可永久清除",避免给 editor/viewer 误导)
    • 单条按钮可见性按角色:owner 看到 [永久删除 + 恢复];editor 只看到 [恢复](永久删除按钮隐藏)
    • 批量删除(④,仅 owner):顶部 "选择" 文本按钮 → 进入选择模式:卡片右上的按钮变身左侧圆形 checkbox + 行内可点切换;header 标题不变(回收站),副标改为"选择要删除的记录",右侧变为"取消"。已选数量只在底部 batch-action-bar 显示一次("已选 N 条 + [永久删除]"),不在顶部重复;N=0 时按钮 disabled。editor 完全看不到顶部"选择"入口
    • 永久删除二次确认 Modal(⑤):无论单条或批量都弹同款 Modal,沿用规范 §4.7 + popups-reference.html:
      • 标题(--text-xl --font-bold --color-fg-strong):"永久删除 N 条记录?"
      • 正文(--text-base --leading-base):"此操作不可撤销。删除后将无法恢复,包括所附的图片与视频。"
      • 按钮行:左 [取消](默认浮起灰胶囊)/ 右 [永久删除](danger 红胶囊,主操作位置)
      • destructive Modal 禁止点遮罩关(§4.7 规则),只能点取消或确认
  • 成员管理 / 里程碑设置 沿用相同 list-card + row 模式,不再单独画
  • "我的资料"编辑:点用户卡右上 ✎ 进 /profile/me,改名字 / 改头像 / 改密码(沿用 Login Onboarding 的字段样式)
