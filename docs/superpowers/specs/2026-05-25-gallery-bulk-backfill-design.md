# 画廊批量补传历史照片 — 产品决策与设计

**日期**: 2026-05-25
**状态**: 已对齐,待实现

## 背景

画廊页定位为"该宝宝所有 `status='ready'` 媒体的汇总视图",数据模型上 `media` 直接挂在 baby 上、`entry_media` 是可选 join,孤儿媒体(无 entry 引用)是合法状态。

当前唯一的媒体上传入口是 entry composer——用户必须**先建一条记录**才能上传照片。这造成一类真实场景无法满足:**用户(任意家庭成员)在使用过程中,想把以前拍过、漏传的宝宝照片补进画廊**,但又不想为每张老照片都编一段文字。

## 产品定位前提

讨论后明确两条语义线:

| | 内容 | 进入门槛 |
|---|---|---|
| **Timeline** | 有故事的瞬间 | 用户主动写了点什么(文字 / 里程碑) |
| **Gallery** | 全部素材 | 只要上传就进 |

Timeline 的差异化价值来自"精挑细选+人写过文字",是 babyloom 区别于 iCloud / 微信相册的护城河,不应被随手照片稀释。

## 决策

### 决策 1: 批量补传入口放在宝宝设置页,不放画廊顶部

- **位置**: 宝宝设置页(profile / 宝宝管理)中的"批量补传历史照片"项
- **不放**: 画廊页顶部的常驻 "+" 按钮
- **不做**: onboarding 步骤里的一次性引导

**理由**:
- 入口的物理位置 = 产品价值主张的声明。藏在设置里 = "这是个偶尔用的工具";放画廊顶上 = "这是日常默认动作",会诱导用户跳过写记录、稀释 timeline。
- 补传不是"新建宝宝那一刻"的一次性事件——每个家庭成员(妈妈、爸爸、奶奶……)加入后都可能产生这个需求,所以 onboarding 一次性引导不合适,工具型常驻入口更对。

### 决策 2: 补传的照片只进画廊,不进 timeline

- 补传产生的是**孤儿媒体**(无 entry 引用),仅在画廊按 `takenAt`(若早于 birthday 则 fallback 到 createdAt)归档显示。
- Timeline 仍然只显示 entry,孤儿媒体不出现。

**理由**:
- 用户没有声明"这是值得记住的故事",产品不该擅自帮他把照片塞进故事流。
- Timeline 的某段时间空白是诚实的——它反映"那段时间没有被记录的故事",而非"那段时间没存照片"。这种诚实驱动用户主动补叙事,而不是用照片假装记录密度。
- 数据模型已天然支持这条边界(entry_media 可选),无需改 schema。

### 决策 3: 必须提供"画廊 → 升级为 entry"的反向通路

补传不进 timeline 的前提是用户能轻松把画廊里的孤儿照片转成 entry。

- 画廊点开孤儿照片(无 entryId) → viewer 增加 "为这张照片写一则记录" 按钮
- 点击 → 跳转 entry composer,media 预填、日期预填(用 takenAt ?? createdAt)
- 提交后该照片归属新 entry;再回画廊点同一张时跳记录详情(沿用现有分流逻辑)

这条路径保证两个面互相增强:**画廊是仓库,timeline 是精选,随时可从仓库挑进精选**。

## 实现范围

下次实现会话需要交付:

1. **后端: 批量上传接口**
   - 创建多条 `media`(status='ready'),不创建 `entry_media`。
   - 复用现有单条上传的存储/缩略图/EXIF 解析链路;接口接收 multipart 或多次单文件请求皆可,选简单的。

2. **前端: 宝宝设置页的批量补传入口**
   - 入口项 "批量补传历史照片"
   - 多选系统相册 → 上传进度 → 完成态(提示 X 张已加入画廊,跳转画廊)

3. **前端: 画廊 viewer 的"创建记录"按钮**
   - 仅对 `entryId == null` 的媒体展示
   - 点击跳 entry composer,带预填参数

## 不在本次范围

- 在 timeline 日期 header 旁显示"本月画廊有 X 张照片"提示标记(讨论中提到但用户选择暂不做)
- 画廊页顶部的常驻上传入口(显式拒绝)
- onboarding 步骤里的导入引导(显式拒绝)
- 批量补传的进度断点续传 / 大批量优化(MVP 先做最朴素的串行/并行上传)

## 相关变更(已落地)

- 画廊查询去除 12 个月时间窗口过滤,改为返回该宝宝所有 `ready` 媒体([gallery.ts](../../../lib/db/queries/gallery.ts))。
- 引入 birthday 哨兵:若 `takenAt < birthday` 则归一化为 null,避免 EXIF 异常的素材(网图、表情包)在画廊里产生"穿越"月份分组。
